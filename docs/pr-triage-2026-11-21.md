## #57 — Bulk dish images and copy analysis

**Head `868e4b2a9616`.** Conflicts with #283.

**The conflict.** Both conflicts are modify/delete on the shared-state
files:

```
CONFLICT (modify/delete): .hermes/SHARED_STATE.md
  deleted in 8d694fd and modified in refs/remotes/pr/57
CONFLICT (modify/delete): .hermes/TASKS.md
  deleted in 8d694fd and modified in refs/remotes/pr/57
```

That is not a real disagreement. `.hermes/` moved out of this repo
into the separate private `gustale-state` repository, precisely
because the `private/state` branch of a **public** repo was readable by
anyone on the internet. PR #57 predates that move and still carries
the old copies. The conflict is the security fix landing on top of a
stale branch.

**What it holds that is unique.** Eight files it adds that are not on
#283:

```
apps/web/src/components/DishCoverHero.tsx
apps/web/src/pages/map.astro
apps/web/src/pages/regions.astro
packages/db/src/migrate.ts
scripts/.gitignore
scripts/README.md
scripts/detect-ai-slop.py
scripts/upload-dish-images.py
```

Of these, `map.astro` and `regions.astro` have since been rewritten
outright on main, so their PR versions are stale rather than
valuable. The one genuinely reusable artefact is
**`scripts/detect-ai-slop.py`** — an AI-slop detector for dish copy.

**But it is not the content gate.** Its own docstring says it scans
`packages/db/src/seed-data.ts` for `canonicalName`,
`shortDescription` and `longDescription`. That is the **seed file**,
not the published Atlas descriptions that the brief asks the gate to
lint. It knows nothing about the ATLAS_STYLE banned words, the
origin-word rule, or the label-versus-wording rule. Its patterns are
different things entirely: em-dash spam, marketing buzzwords, "whether
you're a…" constructions, long sentences, triple-adjective stacks,
floating superlatives.

It also cannot run here: the shebang is hardcoded to
`#!/opt/homebrew/bin/python3.14`, a macOS path.

**Recommendation: close as stale.** The salvage is real but it is
small, it is a different rule set, and the equivalent gate now exists
in this repository as `scripts/check_content_gate.py` — written
against the live API, against ATLAS_STYLE, with a baseline and a
statement-aware origin anchor.

**And this is the reason to close it: the unique work targets a host
that no longer exists.** `scripts/verify-dark-launch.sh` is "the P1-P10
pre-launch checks for the recipes → recipes.gustale.com dark launch".
It is a verifier for serving the recipes site on a SECOND host.

That host is retired. Live, right now:

```console
$ curl -sSI https://recipes.gustale.com/ | head -1
HTTP/2 301   ->  https://gustale.com/recipes
$ curl -sSI https://gustale.recipes/ | head -1
HTTP/2 301   ->  https://gustale.com/recipes
```

`CLAUDE.md` states it as a project rule:

> **`gustale.com` is the only domain.** `gustale.recipes` and
> `recipes.gustale.com` are **redirect-only** … Do not reintroduce them,
> and do not add a second host. … This is Rule 12 in `docs/RULES.md`,
> and the build enforces it.

So #220's unique artefact is **obsolete by design**, not by accident.
Preserving it would mean preserving a checker for an architecture the
project has explicitly retired.

**Recommendation: close as obsolete.** There is no artefact here worth
salvaging, and the files it does touch have moved on.
